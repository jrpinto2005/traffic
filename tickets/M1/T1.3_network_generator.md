# T1.3 — Parametric single-intersection network generator

**Archetype:** Builder · **Depends on:** T1.2, T0.2 · **Implements:** `D-010`, `D-023`

## Context
Produces both halves of a scenario's geometry: the SUMO network files the backend consumes,
and the canonical `Junction` / `SignalizedIntersection` structures the rest of the system
reasons about. They must describe the same intersection, and that correspondence is the
thing most likely to drift.

## Contract

```python
class IntersectionSpec(BaseModel):
    approaches: int = 4                  # >= 3
    lanes_per_approach: int = 2
    approach_length_m: float = 200.0
    speed_limit_mps: float = 13.89       # 50 km/h
    turn_lanes: bool = False             # M1: protected turns, no dedicated turn lanes
    phases: list[PhaseSpec]              # authored; validated against the conflict matrix

def build(spec: IntersectionSpec, out_dir: Path) -> tuple[Path, Network]:
    """Returns (path to the .net.xml, the canonical Network)."""
```

The conflict matrix is **seeded from SUMO's computed junction conflicts** (per T0.2's
findings) and may be overridden by the spec. Phases are authored in the spec and **validated
at load**; a phase containing a `CONFLICTING` pair is a hard error naming the pair (`D-023`).

## Scope
1. Emit `.nod.xml`, `.edg.xml`, `.con.xml`, `.tll.xml`; invoke `netconvert`.
2. Parse the resulting network into canonical types via `sumolib`.
3. Build the three-valued conflict matrix from **static net-file data** (verified in T0.2's
   corrected findings): each junction's `<request index=N response=... foes=...>` rows give
   `foes` (physically conflicting link indices) and `response` (which of those this link yields
   to) — `foes=0` → COMPATIBLE, `foes=1 response=1` → PERMITTED, `foes=1 response=0` →
   CONFLICTING. Protected versus permissive comes from the **case** of the phase state character
   (`G` vs `g`). **Do not use `traci.lane.getLinks()`** — those are runtime values and seeding a
   static matrix from them is a category error.
4. Validate authored phases against it.
5. Emit the SUMO ID ↔ canonical integer ID mapping (`05_DOMAIN_MODEL.md` §1.2).

## Non-goals
1. Do NOT support multiple intersections. That is M5.
2. Do NOT use `netgenerate`. Explicit node and edge files, so the generator generalises to
   grids later.
3. Do NOT generate demand. That is T1.5.
4. Do NOT enumerate phases automatically from the conflict matrix. Authored then validated —
   `D-023`, and automatic enumeration would pollute the action space.
5. Do NOT support permitted turns at M1. The schema has the value; scenarios do not use it.

## Acceptance criteria
- [ ] A default 4-approach spec produces a network SUMO loads without warnings.
- [ ] The canonical `Network` round-trips: every SUMO lane and connection appears exactly
      once, verified by count and by ID.
- [ ] A spec with a phase containing a conflicting pair fails with an error naming the pair.
- [ ] A 3-approach (T-intersection) spec works, proving no four-way assumption is hard-coded
      (`00_RESEARCH_SPECIFICATION.md` §8.1).
- [ ] `validate_network()` from T1.2 passes on every generated network.
- [ ] **The parser also handles a network we did not generate.** Parse RESCO's `cologne1` —
      a real single intersection with a real signal program, vendored at
      `spikes/M0_prior_art/RESCO/` — into canonical types. Parse only, no simulation. This
      catches the failure where the parser silently encodes assumptions that hold only for
      our own generator's output.

## Escalate if
1. SUMO's conflict data cannot populate the three-valued matrix as `D-023` assumes (T0.2
   should have caught this; if it reappears, stop).
2. Canonical and SUMO representations cannot be made to correspond one-to-one.

## Definition of Done
`08_AGENT_HANDOFF_PROTOCOL.md` §5, Builder.

## Amendment, 2026-10-07 — binding; issued with the ticket

Written after T1.4 merged, after `D-034`, and after `D-023`'s seeding rule was corrected. Where
this section and anything above disagree, **this section wins**.

### A1. Conflict matrix: the corrected rule (`D-023`, corrected 2026-10-07)
Scope item 3's table is **superseded**. Foes in either direction → `CONFLICTING`; no foes →
`COMPATIBLE`; `PERMITTED` only where the spec declares a pair permitted, directed by `response`
(see the register for the table). Movement-level entries aggregate their links' entries, most
restrictive wins; the diagonal is `COMPATIBLE`. Three traps, each verified on real nets:

1. **Bit order.** `foes` and `response` run **right to left**: the last character is link 0.
   Only that reading makes `foes` symmetric. Assert symmetry in a test.
2. **Two numberings.** A junction's `<request index>` and a traffic light's `linkIndex` are
   different numberings of the same connections (they disagree on 4 of 16 links of the M0
   probe). The junction index is the middle number of the connection's `via` internal lane,
   `:<junction>_<index>_<lane>`. Map through the connection; never assume they are equal.
3. **netconvert does not honour `linkIndex` written in a `.con.xml`.** Read every `linkIndex`
   back from the built net and write `.tll.xml` states against it — which means building the
   net, reading it, then writing the program and rebuilding. This exact mistake left the M0
   reference program greening crossing movements for seven weeks.

### A2. Canonical IDs follow sorted SUMO IDs (`05_DOMAIN_MODEL.md` §7)
`LaneId(i)` is the *i*-th of **all** SUMO lane IDs in sorted order, internal (`:`) lanes
included — the order `traffic_lab.backend.BackendIndex` already uses, so `TrueState` and
`Network` name the same lanes. `EdgeId`, `JunctionId`, `IntersectionId` likewise over edges
(internal included), junctions and traffic-light IDs. `LaneConnectionId` and `MovementId`: any
deterministic order, documented. Internal lanes are therefore `Network.lanes`, of internal
edges. Canonical `LaneConnection`s are SUMO's connections **between normal lanes**; connections
out of internal lanes are represented by the internal lane itself, and the round-trip test
counts accordingly and says so. If this cannot satisfy §8 invariants 1–5, **stop and escalate**
(condition 2) — do not invent a second ID space.

### A3. `controlled_connections` and green links (`D-034`)
- Add `controlled_connections: tuple[LaneConnectionId, ...]` to `SignalizedIntersection`
  (position = `linkIndex`). Update every constructor in `tests/`; `validate_network()` keeps
  passing. Two connections sharing one `linkIndex`: escalate.
- Add to `domain/network.py`:
  `green_link_indices(network, intersection_id, phase_id) -> frozenset[int]` — the link indices
  a phase shows green. Write `.tll.xml` from it. T1.14 decodes SUMO's display with it.

### A4. The spec, made concrete
- `PhaseSpec.green: list[tuple[int, TurnDirection]]` — the (approach, turn) pairs green in the
  phase. Approach *k* of *n* sits at bearing 360·*k*/*n* degrees clockwise from north.
- `IntersectionSpec.timing: SignalTiming` — **required, no default**: it affects results.
- `TurnDirection` from the connection's `dir`: `s` → THROUGH, `l`/`L` → LEFT, `r`/`R` → RIGHT,
  `t` → U_TURN. Anything else: escalate.
- The emitted static program runs the authored phases in order — green `min_green_s`, yellow
  `yellow_s`, all-red `all_red_s` (omitted when 0) — and is in effect **only until the first
  `apply()`**. Say so in a comment: a reader will otherwise take it for a baseline.
- Code lives in `traffic_lab/scenarios/` (spec types and `build()`); tests in
  `tests/scenarios/` with an `__init__.py`.

### A5. Import boundary
`tests/backend/test_backend_import_boundary.py` forbids `sumolib` outside `backend/`. That is
stricter than `06_ARCHITECTURE.md` §10 rule 2 (clarified 2026-10-07) and incompatible with this
contract. Amend the test to also allow `sumolib` in `traffic_lab/scenarios/`; `traci` and
`libsumo` stay backend-only.

### A6. `cologne1` is GPL and gitignored
RESCO (GPLv3) is cloned at `spikes/M0_prior_art/RESCO/` in the main checkout and ignored by git.
In a worktree, symlink that directory; **never copy any RESCO file into the repository.** The
test locates it from the repository root and skips with an explicit reason only when the clone
is absent. The completion report must show it **ran**.

### A7. Added acceptance criteria
- [ ] Starting `SumoBackend` on a generated net yields `BackendIndex.lane_sumo_ids` and
      `intersection_sumo_ids` in exactly the order of the generator's ID mapping.
- [ ] `foes` read from every generated junction, and from `cologne1`'s, are symmetric.
- [ ] For each authored phase, the links SUMO actually shows green at runtime
      (`trafficlight.getControlledLinks` against the displayed state) are exactly the
      connections of that phase's movements. This is the test that would have caught the M0
      reference program.
- [ ] A generated network loads in SUMO with **no** warnings — run without `--no-warnings`.
