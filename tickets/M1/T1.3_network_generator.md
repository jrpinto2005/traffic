# T1.3 — Parametric single-intersection network generator

**Archetype:** Builder · **Depends on:** T1.2, T0.2 · **Implements:** `D-010`, `D-023`

## Context
Produces both halves of a scenario's geometry: the SUMO network files the backend consumes,
and the canonical `Junction` / `SignalizedIntersection` structures the rest of the system
reasons about. They must describe the same intersection, and that correspondence is the
thing most likely to drift.

## Contract

```python
class IntersectionSpec(BaseModel):
    approaches: int = 4                  # >= 3
    lanes_per_approach: int = 2
    approach_length_m: float = 200.0
    speed_limit_mps: float = 13.89       # 50 km/h
    turn_lanes: bool = False             # M1: protected turns, no dedicated turn lanes
    phases: list[PhaseSpec]              # authored; validated against the conflict matrix

def build(spec: IntersectionSpec, out_dir: Path) -> tuple[Path, Network]:
    """Returns (path to the .net.xml, the canonical Network)."""
```

The conflict matrix is **seeded from SUMO's computed junction conflicts** (per T0.2's
findings) and may be overridden by the spec. Phases are authored in the spec and **validated
at load**; a phase containing a `CONFLICTING` pair is a hard error naming the pair (`D-023`).

## Scope
1. Emit `.nod.xml`, `.edg.xml`, `.con.xml`, `.tll.xml`; invoke `netconvert`.
2. Parse the resulting network into canonical types via `sumolib`.
3. Build the three-valued conflict matrix from SUMO's junction request/response data.
4. Validate authored phases against it.
5. Emit the SUMO ID ↔ canonical integer ID mapping (`05_DOMAIN_MODEL.md` §1.2).

## Non-goals
1. Do NOT support multiple intersections. That is M5.
2. Do NOT use `netgenerate`. Explicit node and edge files, so the generator generalises to
   grids later.
3. Do NOT generate demand. That is T1.5.
4. Do NOT enumerate phases automatically from the conflict matrix. Authored then validated —
   `D-023`, and automatic enumeration would pollute the action space.
5. Do NOT support permitted turns at M1. The schema has the value; scenarios do not use it.

## Acceptance criteria
- [ ] A default 4-approach spec produces a network SUMO loads without warnings.
- [ ] The canonical `Network` round-trips: every SUMO lane and connection appears exactly
      once, verified by count and by ID.
- [ ] A spec with a phase containing a conflicting pair fails with an error naming the pair.
- [ ] A 3-approach (T-intersection) spec works, proving no four-way assumption is hard-coded
      (`00_RESEARCH_SPECIFICATION.md` §8.1).
- [ ] `validate_network()` from T1.2 passes on every generated network.
- [ ] **The parser also handles a network we did not generate.** Parse RESCO's `cologne1` —
      a real single intersection with a real signal program, vendored at
      `spikes/M0_prior_art/RESCO/` — into canonical types. Parse only, no simulation. This
      catches the failure where the parser silently encodes assumptions that hold only for
      our own generator's output.

## Escalate if
1. SUMO's conflict data cannot populate the three-valued matrix as `D-023` assumes (T0.2
   should have caught this; if it reappears, stop).
2. Canonical and SUMO representations cannot be made to correspond one-to-one.
