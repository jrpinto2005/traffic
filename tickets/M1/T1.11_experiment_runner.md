# T1.11 — Experiment runner: sweeps, seeds, parallelism

**Archetype:** Builder · **Depends on:** T1.1, T1.8 · **Implements:** `D-017`, `D-031`, `D-008`

## Context
Turns a config into N independent runs and their results. Per `D-031` the runner is designed
around **N independent runs, not one run in a loop** — that is the largest performance lever
available (near-linear in cores), it is nearly free designed in from the start, and it
composes with LibSUMO's one-simulation-per-process constraint rather than working around it.

## Contract

```python
class ExperimentSpec(BaseModel):
    scenario: IntersectionSpec
    demand_levels: list[float]
    controllers: list[ControllerSpec]
    n_seeds: int
    master_seed: int
    warmup_design: WarmupDesign = WarmupDesign.SELF
    jobs: int = 0            # 0 = cpu_count - 1

def run(spec: ExperimentSpec, out: Path) -> Path   # returns the parquet path
```

**Seed derivation** (`D-017`): independent streams — `demand`, `driver`, `sensor`,
`estimator`, `policy` — derived from the master seed by a documented scheme, so any single
source can be held fixed while others vary.

**Common random numbers:** the same master seed must produce **the same vehicle arrivals
regardless of which controller runs.** Comparisons are paired. This is variance reduction, not
bookkeeping — it is the reason the same conclusion needs several times fewer runs.

Each run is self-contained: own config, own derived seeds, own process, own output, **no
shared mutable state.** A worker crash fails its run and no other.

## Scope
1. Config expansion into run specs (controller × demand level × seed).
2. Seed derivation, documented.
3. Process-pool execution bounded by `jobs`.
4. Per-run parquet plus manifest; concatenation into one experiment parquet.
5. Invalid runs written with their flag (`D-008`), never dropped.
6. Progress reporting suitable for a long sweep.

## Non-goals
1. Do NOT use threads or async. Processes. `06_ARCHITECTURE.md` §11.
2. Do NOT compute statistics. That is T1.12.
3. Do NOT add a job queue, scheduler, or distributed execution. One machine.
4. Do NOT retry failed runs automatically — a silent retry hides a real failure.
5. Do NOT enable trace writing by default. `D-009`.

## Acceptance criteria
- [ ] **Two controllers run with the same master seed receive identical arrival sequences**,
      verified by comparing generated route files. This is the ticket's most important test.
- [ ] Holding `demand` fixed while varying `sensor` changes nothing about arrivals.
- [ ] A sweep of 4 controllers × 3 demand levels × 10 seeds completes and yields 120 rows.
- [ ] A deliberately crashed worker fails exactly one run.
- [ ] Invalid runs appear in the output with their flag.
- [ ] Speedup across cores is measured and reported.

## Escalate if
1. Common random numbers cannot be guaranteed across controllers — this is fundamental to
   `D-017` and to every comparison the project will make.
2. LibSUMO's one-simulation-per-process constraint interacts badly with the process pool.

## Definition of Done
`08_AGENT_HANDOFF_PROTOCOL.md` §5, Builder. Include the parallel speedup number.

## Amendment, 2026-10-07 — binding; issued with the ticket

Written after T1.8, T1.9, T1.14 and T1.15 merged. The original contract depends on things that do
not exist yet — `ControllerSpec` (T1.10), demand levels and generated routes (T1.5) — so this
ticket is **split**. Where this section and anything above disagree, **this section wins**.

### A1. What this ticket builds now: the run core
Everything a sweep needs except deciding *what* to sweep: one run executed end to end, many runs
in a process pool, their outputs and manifests, crash isolation, and SUMO's warnings captured.
`ExperimentSpec`, `ControllerSpec`, demand levels, sweep expansion, the 4 × 3 × 10 acceptance
test and the route-level common-random-numbers test move to **T1.16**, issued after T1.5 and
T1.10. Do **not** add placeholders for them.

### A2. Contract
- `traffic_lab/control/controller.py`: the `Controller` protocol **exactly** as T1.10's contract
  writes it (`decision_interval_s`, `decide(est, now_s) -> PhaseRequest`). T1.10 implements
  controllers against it; you only define it. Test controllers live in `tests/`.
- `traffic_lab/experiments/runner.py`:
  - `RunSpec` — fully resolved and picklable: run ID, net file, routes file, the canonical
    `Network`, a top-level controller factory `Callable[[Network], Controller]`, the T1.1
    `RunConfig`, the seed index, transport (default `libsumo`), step length, output directory.
  - `run_one(spec) -> Path` executes `06_ARCHITECTURE.md` §6.2's loop literally: every step
    `backend.step()`, `project()`, `constraint_layer.step()`, `accumulate()`; every Δt the oracle
    sensor, the identity estimator (signals from the constraint layer, `D-033`), the controller
    and `submit()`. The display is applied with `display_state()` **only when it changes** —
    T1.14 measured 15 % of a LibSUMO step for a call every step. Run phases and the
    measurement window come from `RunConfig` and T1.8's `MeasurementWindow`. At the end:
    `read_trips(..., end_s=...)`, `finalize`, and the outputs below.
  - `run_many(specs, out, *, jobs) -> Path` — a `ProcessPoolExecutor` with the `spawn` context
    and `max_tasks_per_child=1`: **a fresh process per run.** LibSUMO holds one simulation per
    process, and T1.4 showed a replay depends on the process's RNG history, so reusing a worker
    would make results depend on scheduling. Concatenates per-run results into one experiment
    Parquet; returns its path.
- **Seeds (`D-017`).** Add `derive_run_seeds(master_seed, seed_index)` in
  `experiments/seeds.py` (spawn the run's `SeedSequence` from the master, then the five streams),
  documented. It must not take the controller, which is what makes arms comparable: the same
  `(master_seed, seed_index)` gives the same streams to every controller. `driver` →
  `BackendConfig.seed`; the others are recorded in the manifest.
- **SUMO warnings.** Replace the console-silencing `--no-warnings` alone with
  `--error-log <run dir>/sumo-warnings.log` **plus** `--no-warnings true` — verified 2026-10-07:
  the console stays silent and every warning lands in the file. `BackendConfig` gains the log
  path. The manifest records `sumo_warnings` (count of warning lines). Reported, not an
  invalidity cause: that would be a new decision. `--no-warnings` alone hid two real defects
  this week.
- **Outputs per run:** `result.parquet` (T1.8's row), `manifest.json` (T1.1's manifest with the
  real validity and trip accounting, canonical counter names), `tripinfo.xml`,
  `sumo-warnings.log`. Invalid runs are written with their flags (`D-008`). A run that
  **crashes** produces no result row; it is recorded in a `failures.parquet` with its run ID and
  exception text. No retry.
- Progress: one line per finished run on stderr (done / failed / invalid counts, elapsed).

### A3. Acceptance criteria, replacing the list above
- [ ] **Reproducibility:** the same `RunSpec` run twice, in fresh processes, gives identical
      result rows (wall-clock and memory columns excepted).
- [ ] **Common random numbers, seed level:** two `RunSpec`s differing only in controller get
      identical derived seeds and identical `TrueState` vehicle-arrival sequences up to the first
      step their controllers act differently.
- [ ] A deliberately crashing controller fails exactly one run; the others complete; the
      failure is in `failures.parquet`.
- [ ] An overloaded run appears in the experiment Parquet flagged invalid.
- [ ] An out-of-order route file yields `sumo_warnings >= 1` in the manifest and nothing on the
      console.
- [ ] The display is applied only on change (count `apply()` calls in a test).
- [ ] Speedup measured and reported: the same N runs at `jobs=1` and at `jobs=k`.

### A4. Escalate if
- `max_tasks_per_child=1` with `spawn` interacts badly with LibSUMO (original escalation 2).
- Any piece merged so far cannot be composed as §6.2 says without changing its contract.

| Speedup | 16 one-hour runs, Apple M3 (4P + 4E): 1.98× / 3.44× / 4.42× at jobs 2 / 4 / 8 | ✅ |

**§6.2 pinned by tests:** a state at every step to the run's end; decision k at k·Δt from Δt on
(steps/Δt of 1/1, 1/5, 0.5/1, 0.5/2.5); window queues over exactly [warm-up end, measurement end);
the controller sees the phase being entered mid-transition while truth shows the one being left.

**Rulings during the audit:** one spawn process per run instead of a process pool (a dying worker
broke the whole pool); gridlock N derived from the signal timing (`D-008`, owner); the manifest
carries the full resolved run and the net and routes file hashes; a network with no signalized
intersection is refused. Seeds now fit SUMO's signed int32 (found by T1.5's builder).

**Profile of one hour** (cProfile, ~99 vehicles): `step()` + `project()` 2.58 s of 2.95 s; the
oracle sensor 0.134 s; everything the runner adds is small. A fresh process costs about 1 s per
run, mostly imports — the price of isolation, accepted. **Open:** T1.4's gap 4 (`RawStep.arrived`).
