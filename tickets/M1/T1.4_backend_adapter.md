# T1.4 — Backend adapter: transport, subscriptions, projection

**Archetype:** Builder · **Depends on:** T1.2, T0.3 · **Implements:** `D-002`, `D-003`, `D-008`, `D-031`

## Context
The **only** code in the project that talks to SUMO. `00_RESEARCH_SPECIFICATION.md` §25 makes
that a hard architectural boundary and `06_ARCHITECTURE.md` §10 enforces it as a test. This is
the most performance-sensitive and most correctness-sensitive ticket in M1.

## Contract

```python
class Backend(Protocol):
    def start(self, net: Path, routes: Path, cfg: BackendConfig) -> None: ...
    def step(self) -> None: ...
    def project(self) -> TrueState: ...
    def apply(self, intersection: IntersectionId, phase_state: str) -> None: ...
    def save_state(self, path: Path) -> None: ...      # D-032
    def load_state(self, path: Path) -> None: ...      # D-032
    def close(self) -> None: ...

class BackendConfig(BaseModel):
    transport: Literal["traci", "libsumo"] = "traci"   # D-002
    step_length_s: float = 1.0
    seed: int
    time_to_teleport_s: float = -1.0                   # D-008; -1 disables
```

**One batched projection per step.** `project()` performs **one batched fetch** and builds
`TrueState`. The adapter exposes **no per-object query method** to the rest of the system. Per
`D-031` this is an architectural constraint, not an optimization.

**The batching mechanism is transport-specific** (amended after T0.3 measured it): variable and
context subscriptions under TraCI, where they are ~10× faster than polling; direct batched
getters under LibSUMO, where subscriptions are ~1.7× *slower* because there is no socket to
amortise. Implement both. The byte-identical-`TrueState` acceptance test below is what
guarantees they cannot diverge.

**Startup assertions** (`D-008`, `06_ARCHITECTURE.md` §5.4) — each a hard failure:
`time_to_teleport_s == -1`; `step_length_s` divides the configured decision interval; a
loaded snapshot's network hash matches; the SUMO version matches the manifest when loading a
snapshot.

## Launch flags (from T0.1 §9.1 — adopt these)

| Flag | Why |
| --- | --- |
| `--time-to-teleport -1` | `D-008`. Passed **and asserted**. |
| `--tripinfo-output.write-unfinished true` | Gives `D-022`'s "still in-network" leg natively, per vehicle rather than as a bare counter. |
| `--tripinfo-output.write-undeparted true` | Same for insertion loss. |
| `--eager-insert` | Required for undeparted vehicles to be written correctly. **Carries a performance cost** — measure and report it, per `D-031`. |
| `--no-step-log true`, `--duration-log.disable true` | Removes per-step console I/O from the hot loop. |

The first three turn `D-008` and `D-022`'s accounting from something we compute into something
SUMO reports, which removes a class of our own arithmetic errors.

**Validity counters come from one subscription, not from bookkeeping.** T0.1 found PyTSC
obtains `n_teleported`, `n_colliding`, `n_emergency_brakes`, `n_loaded`, `n_departed`,
`n_arrived` in a single `simulation.subscribe` call — exactly `D-008`'s counter set at zero
per-step cost. Copy the subscription list; add the acting-on-it that PyTSC omits.

**Study before writing this ticket:** PyTSC's `common/` + `backends/` split is the cleanest
available illustration of where the `D-002` seam falls — abstract `simulator`, `retriever`,
`network_parser`, `traffic_signal`, `metrics`, with one concrete package per backend. Vendored
at `spikes/M0_prior_art/PyTSC/`.

## Scope
1. `Backend` with two transports behind one interface, selected by config.
2. Subscription registration and the single batched per-step fetch.
3. Projection into `TrueState`, including `RunCounters` (teleports, insertion failures,
   gridlock, trip accounting).
   **You own invariants 10–12** of `05_DOMAIN_MODEL.md` §8: every vehicle on exactly one lane,
   `is_halting` ⟺ `speed_mps < 0.1`, and `queue_count` counting exactly the vehicles halting for
   ≥ 1 s. `domain/` uses frozen dataclasses that cannot self-validate cross-field properties, so
   the adapter must **uphold** these when projecting rather than assume them. Add property-based
   tests that a projected `TrueState` satisfies all three.
4. Startup assertions.
5. Gridlock detection: no vehicle has moved for N steps, N configurable.

## Non-goals
1. Do NOT expose per-object getters. Not even "just for debugging".
2. Do NOT compute metrics. Counters yes, metrics no — that is T1.8.
3. Do NOT implement snapshot policy. The mechanism only; policy is T1.6.
4. Do NOT add a caching layer. `D-031` — nothing has been profiled.
5. Do NOT add a third transport or a generic simulator interface above `Backend`.
   `06_ARCHITECTURE.md` §11.

## Acceptance criteria
- [ ] The same scenario produces byte-identical `TrueState` sequences under both transports.
      **This is the ticket's most important test.**
- [ ] A test asserts the adapter issues **one** state-fetch call per step, regardless of
      vehicle count.
- [ ] Each startup assertion has a test proving it fails loudly.
- [ ] Wall-clock per simulated hour is within the range T0.3 measured; report the number.
- [ ] An import test asserts only `traffic_lab.backend` imports `traci` or `libsumo`.

## Escalate if
1. The two transports produce different state — investigate, do not paper over it.
2. A field `TrueState` requires is unavailable via subscription and would need polling.
3. `save_state` / `load_state` differ between transports.
