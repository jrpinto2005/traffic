# T1.1 — Package skeleton, configuration, run manifest

**Archetype:** Builder · **Depends on:** T0.0 · **Implements:** `D-004`, `D-014`

## Context
The scaffolding every other ticket builds on: the package layout, typed configuration, and
the run manifest that makes `02_PROJECT_CHARTER.md` S1 true. A result without a manifest is
not a result.

## Contract

Package layout exactly as `D-014` specifies. **Create only the subpackages this ticket
populates** — `experiments/` — plus an empty `traffic_lab/__init__.py`. Per `D-014` no
directory is created before code goes into it.

```python
class RunManifest(BaseModel):
    config_hash: str                 # sha256 of the canonical serialised config
    config: dict                     # fully resolved, defaults included
    code_version: str                # git SHA, suffixed "-dirty" if the tree is dirty
    sumo_version: str
    seeds: dict[str, int]            # per stream, per D-017
    decision_interval_s: dict[str, float]   # per controller, per D-020
    warmup_design: Literal["self", "neutral_snapshot"]   # D-032
    validity: dict[str, int | bool]  # D-008 counters
    trips: dict[str, int]            # D-022 three-way accounting
    wall_clock_s: float
    peak_memory_mb: float
```

Config loading: YAML → Pydantic v2, validated at load. An invalid config fails **before**
the simulator starts, with an error naming the offending field.

## Scope
1. `pyproject.toml` for the `traffic_lab` package; ruff and mypy configured, mypy strict on
   `traffic_lab.domain`.
2. Config loading with Pydantic v2 from YAML, including config-hash computation.
3. `RunManifest` and its serialisation to JSON alongside results.
4. Git SHA and dirty-tree detection.
5. A CLI entry point stub: `traffic-lab run <config>` that loads, validates, prints the
   manifest, and exits. It does not simulate yet.
6. `configs/smoke.yaml` — the minimal config this ticket's own schema can express, used as
   the acceptance fixture here and by T1.13.

**On the smoke config's scope.** At T1.1 the config schema covers only run identity, seeds,
and run phases — the scenario and demand schemas do not exist yet (T1.3, T1.5). `smoke.yaml`
therefore holds *only* those fields. Later tickets extend both the schema and this file.
Do not stub scenario or demand fields in anticipation; an unpopulated field that nothing reads
is a `D-031` anti-pattern.

## Non-goals
1. Do NOT create empty subpackages. `D-014`.
2. Do NOT build the experiment runner. That is T1.11.
3. Do NOT add a plugin or registry system for configs. `D-031` anti-patterns.
4. Do NOT add logging frameworks, DI containers, or a settings singleton.

## Acceptance criteria
- [ ] `traffic-lab run configs/smoke.yaml` prints a complete manifest and exits 0.
- [ ] An invalid config fails at load with a message naming the field.
- [ ] The same config produces the same `config_hash` across runs and machines.
- [ ] A dirty working tree produces a `code_version` ending in `-dirty`.
- [ ] `mypy --strict traffic_lab/` clean; `ruff check` clean.

## Escalate if
1. Any manifest field cannot be obtained at run start (e.g. SUMO version before the
   simulator is launched).
2. Config-hash stability conflicts with Pydantic's serialisation of any field type.
