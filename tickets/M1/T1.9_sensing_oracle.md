# T1.9 — Sensing interface, oracle sensor, identity estimator

**Archetype:** Builder · **Depends on:** T1.2 · **Implements:** `D-005`, `D-021`, charter S6

## Context
**Small ticket, load-bearing architecture.** Per `06_ARCHITECTURE.md` §4.1 the oracle is
**a sensor, not a bypass**: `OracleSensor` implements the same interface as the camera model
will at M3, and returns perfect observations. The consequence is that a controller receives
`EstimatedState` in *every* experimental arm including the oracle, and `traffic_lab.control`
never imports `TrueState` at all.

There is no path to leak through because there is no path. That is `02_PROJECT_CHARTER.md`
S6, and it only holds if this ticket exists at M1 rather than being retrofitted at M3.

## Contract

```python
class SensorModel(Protocol):
    def observe(self, state: TrueState, now_s: float) -> Observation: ...

class Estimator(Protocol):
    def update(self, obs: Observation, now_s: float) -> EstimatedState: ...

class OracleSensor:       # detection probability 1.0, zero noise, zero latency
class IdentityEstimator:  # passes observation through; queue_count_std = 0.0
```

`Observation` and `EstimatedState` are exactly as `05_DOMAIN_MODEL.md` §4 specifies. Note
especially that **nothing in `Observation` references field of view, range, or detection
probability** — per `D-005` a pixel-derived detection stream must substitute for the
parametric one with no downstream change, and that is only true if the type does not encode
the parametric model.

`observed_lanes` is populated even by the oracle (with all lanes). Absence of a detection on
a covered lane is evidence of absence; on an uncovered lane it is no evidence at all, and an
estimator that cannot tell those apart gets every partial-sensing result wrong in the same
direction.

## Scope
1. The two protocols.
2. `OracleSensor`, `IdentityEstimator`.
3. An import test asserting `traffic_lab.control` does not transitively import `TrueState`.

## Non-goals
1. Do NOT implement a camera model. That is M3.
2. Do NOT implement counting-with-decay estimation. That is M3, and `D-021` is still OPEN.
3. Do NOT add noise, latency, or dropout parameters — not even disabled ones.
4. Do NOT let a controller accept `TrueState` "for the oracle case". That is the entire point.

## Acceptance criteria
- [ ] `OracleSensor` produces one detection per vehicle, zero uncertainty, `observed_lanes`
      containing every lane.
- [ ] `IdentityEstimator` round-trips oracle observations into an `EstimatedState` whose
      queue counts equal the true ones exactly.
- [ ] **The import test passes and fails correctly** — verify it by temporarily adding an
      illegal import and confirming the test catches it.
- [ ] `mypy --strict` clean; a controller signature typed against `TrueState` fails type
      checking.

## Escalate if
1. A controller planned for T1.10 needs a quantity `EstimatedState` does not carry —
   **escalate rather than widening the type**, since what a controller may know is the
   project's central research question.
