# T1.16 — Experiment spec and sweep expansion

**Archetype:** Builder · **Depends on:** T1.5, T1.10, T1.11 · **Implements:** `D-017`, `D-013`

## Context
Split from T1.11 on 2026-10-07: the run core (T1.11) could be built before demand generation and
controllers existed; deciding *what* a sweep runs could not. This ticket carries the original
T1.11 contract's `ExperimentSpec` and the acceptance criteria that need T1.5 and T1.10.

## Contract
The original T1.11 `ExperimentSpec` — `scenario`, `demand_levels`, `controllers:
list[ControllerSpec]`, `n_seeds`, `master_seed`, `warmup_design`, `jobs` — expanded into
T1.11's `RunSpec`s (controller × demand level × seed). Route files come from T1.5's
`build_routes` with the run's `demand` stream seed, so they depend on (demand level, seed) and
**never** on the controller. `ControllerSpec` maps to T1.10's controllers. Only
`warmup_design="self"` until T1.6 lands. **The SUMO gap-actuated arm** (T1.10 A4) runs on the net built
with `program="actuated"` and with no constraint layer and no `apply()`: the runner needs that
mode, and this ticket adds it.

## Acceptance criteria
- [x] **Two controllers run with the same master seed receive identical arrival sequences**,
      verified by comparing generated route files. The original T1.11's most important test.
- [x] Holding `demand` fixed while varying `sensor` changes nothing about arrivals.
- [x] A sweep of 4 controllers × 3 demand levels × 10 seeds completes and yields 120 rows.
- [x] The experiment Parquet records each run's controller, Δt, demand level and seed index.

### Key design decisions
1. **Route file sharing:** Route files are generated once per `(demand_level, seed_index)` cell using `seeds["demand"]`. All controller arms within the cell execute against the identical route file.
2. **Native SUMO arm:** In `RunSpec` when `controller_factory is None`, the simulation steps without a `ConstraintLayer` or `apply()` calls, recording zero constraint layer overrides while accumulating standard network metrics.
3. **Execution speed:** 120 parallel runs execute across 4 worker processes in ~21 seconds in LibSUMO.
