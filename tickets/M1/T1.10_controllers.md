# T1.10 — Baseline controllers: Webster, actuated, Max-Pressure

**Archetype:** Builder · **Depends on:** T1.7, T1.9, T1.14 · **Implements:** `D-013`, `D-020`

## Context
Per `D-013` these four are the **mandatory baseline set**: no advanced controller may be
reported until it has been compared against all of them on identical seeds. Their correctness
is therefore load-bearing for every result the project will ever produce — **a buggy baseline
manufactures fake improvement**, and a badly tuned one does the same.

## Contract

```python
class Controller(Protocol):
    decision_interval_s: float                                   # D-020
    def decide(self, est: EstimatedState, now_s: float) -> PhaseRequest: ...
```

Controllers receive `EstimatedState` only. There is no `TrueState` in scope.

| Controller | Δt | Requirement |
| --- | --- | --- |
| **Webster fixed-time** | schedule-driven | Cycle length and green splits computed by **Webster's method for the demand being tested** — not an arbitrary equal split. Document the formula and the critical-flow-ratio estimation. |
| **Actuated (ours)** | 1 s | Gap-based extension with min/max green. Δt must be fine: a coarse interval blunts gap-out into a different algorithm. |
| **SUMO gap-actuated** | n/a | Wire SUMO's own `type="actuated"` program as an independent cross-check. If ours diverges greatly from SUMO's, one of them has a bug. |
| **Max-Pressure** | 5 s | Pressure = upstream minus downstream queue counts over a phase's movements; select the maximum-pressure phase. Queue counts per `D-025`. |

## Starting priors from the literature (T0.1 §9.2)

Defaults, not decisions — the field's centre of mass, so ours are defensible and the `D-020`
Δt sensitivity check has a reference point.

| Parameter | Consensus | Note |
| --- | --- | --- |
| Δt | **5 s** | RESCO, PyTSC and sumo-rl all use it; LibSignal uses 10 s |
| Yellow | **3 s** | Most defensible; RESCO cites Ma & Wu |
| All-red | 2 s | Only RESCO models it at all |
| Min green | 5–10 s | Wide spread — ours is a real decision, not a copy |
| Max green | 50–60 s | |
| Episode | 3600 s | Universal across all four |

**Two cautions carried from T0.1.** RESCO has *no* min or max green and consumes yellow and
all-red from inside its 5 s decision interval, so a switching signal can receive 0–2 s of
actual green — timings that would be illegal in the field. And every fixed-time baseline in
the surveyed set is an equal split, which is exactly what `D-013` exists to prevent. Copy
neither.

Replication counts in the prior art run from 1 to 10. `D-017`'s ≥30 paired seeds is a
methodological improvement over the field, and the results document should say so.

## Scope
1. The four above, each acting through T1.7's constraint layer.
2. Webster computation as a documented, separately testable function.
3. Per-controller Δt configuration with the defaults above.
4. Per-outcome counters from the constraint layer surfaced into the manifest — "the policy
   requested an illegal switch 400 times" is diagnostic information, not something to swallow.

## Non-goals
1. Do NOT implement MPC, RL, SOTL, or Max-Wave. M6, M7, optional.
2. Do NOT implement coordination or offsets. That is M5b.
3. Do NOT add a controller base class or registry. A `Protocol` with one method. `D-031`.
4. Do NOT tune Max-Pressure with heuristics beyond its definition — the point is the
   published algorithm, not our variant of it.
5. Do NOT let any controller read `TrueState`, including "just for Webster's demand estimate".
   Webster is computed offline from the **configured** demand, not observed state.

## Acceptance criteria
- [ ] Webster's computed cycle length matches a hand-worked textbook example.
- [ ] Fixed-time produces exactly its scheduled phase sequence over many cycles.
- [ ] Our actuated and SUMO's gap-actuated agree within a stated tolerance on the same
      scenario and seed — **or the discrepancy is investigated and explained in writing.**
- [ ] Max-Pressure selects the hand-computed maximum-pressure phase on a fixture with known
      queues.
- [ ] No controller ever produces a REJECTED outcome on a valid network (they should never
      request an illegal phase).
- [ ] The import test from T1.9 still passes.

## Escalate if
1. Our actuated and SUMO's disagree and the cause is not found. Do not paper over it — one
   of them is wrong and we need to know which.
2. Max-Pressure needs a quantity `EstimatedState` does not carry (most likely downstream
   queue counts at a boundary). This is a real design question, not a detail.
3. Webster's method needs a demand estimate the config does not provide.

## Amendment, 2026-10-08 — binding; issued with the ticket

Written after T1.5, T1.8, T1.9, T1.11, T1.14 and T1.15 and decisions `D-033` to `D-037`. Where this
section and anything above disagree, **this section wins**.

### A1. Inputs every controller has
`decide(est, now_s)` per the `Controller` protocol in `traffic_lab/control/controller.py`
(defined by T1.11 — implement against it, do not redefine it). `est.signals` is the constraint
layer's own view (`D-033`); `est.lanes` carries `queue_count` and `zone_count` (`D-036`).
Static inputs — the canonical `Network`, and for Webster the configured `DemandSpec` and the
saturation-flow calibration — arrive through the constructor. Nothing reads `TrueState`.

### A2. Webster — now computable (`D-037`)
- Movement flow = source rate (`rate_saturation_fraction` × approach saturation flow, T1.5) ×
  turn ratio. Per-lane saturation flow per turn from `lookup_calibration` /
  `per_lane_saturation_flow_vph` (T1.5). Flow ratio of a movement = flow / (per-lane
  saturation flow × lanes serving it); `y_i` = the largest ratio among a phase's movements;
  `Y = Σ y_i`.
- Lost time per phase = `yellow_s + all_red_s` — the HCM default, in which a 2 s start-up loss
  and a 2 s yellow extension cancel. Document it. `C₀ = (1.5 L + 5) / (1 − Y)`; effective greens
  `(C₀ − L) · y_i / Y`.
- Greens are rounded to the step length, clamped to `[min_green_s, max_green_s]`, and every
  clamp is **reported**, never silent. `Y ≥ 1` raises: Webster is undefined there, and the sweep
  must not ask for it.
- Executed at Δt = 1 s by requesting the next authored phase once the current green has lasted
  its planned length (`est.signals`' `green_started_s`); the constraint layer inserts the
  clearances.
- The textbook check uses a published worked example with its source cited.

### A3. Actuated (ours) — presence mode on the detection zone (`D-036`)
At Δt = 1 s: before `min_green_s`, hold; afterwards extend while any lane served by the green
phase has `zone_count > 0`, and request the next authored phase once those zones have been empty
for longer than the gap time. Max green is the constraint layer's. **Verify SUMO 1.27.1's
actuated defaults** (`max-gap`, `detector-gap`, `passing-time`, and whether empty phases are
skipped) against SUMO itself, and give ours the same gap time, the same zone length (`zone_s` =
SUMO's `detector-gap`) and the same skipping behaviour. If `D-036`'s 2.0 s does not match
SUMO's default, escalate.

### A4. SUMO gap-actuated
`traffic_lab.scenarios.build` gains a keyword `program: Literal["static", "actuated"] =
"static"` writing a `type="actuated"` program with `minDur = min_green_s` and `maxDur =
max_green_s` on the green phases and the same clearances, with the actuated parameters set
explicitly to the values A3 verified. In that arm SUMO drives the light: no constraint layer,
no `apply()`. The cross-check drives `SumoBackend` directly in tests (as T1.14 did); wiring the
SUMO arm into the runner is T1.16's. State the tolerance before measuring — e.g. mean delay
within 10 % at two demand levels over ten seeds — and explain any miss in writing.

### A5. Max-Pressure — lane-level form
At each decision: for each authored phase, `U` = the incoming lanes of its movements, `D` = their
outgoing lanes (each lane once); pressure = `Σ_U queue_count − Σ_D queue_count`. Request the
maximum; on a tie keep the current phase, else the lowest phase ID. This is the lane-level form
used in the traffic-signal-control literature (cite the source in the docstring); no weights,
no heuristics (Non-goal 4). Escalate-if 2 is answered: outgoing lanes are in `EstimatedState`.
