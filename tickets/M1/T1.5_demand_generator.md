# T1.5 — Demand: sources, turn ratios, attrition, sinks

**Archetype:** Builder · **Depends on:** T1.3, T0.5 · **Implements:** `D-022`, `D-017`

## Context
The owner-specified open-boundary flow model: vehicles are **not conserved** inside the study
area. They enter from Poisson sources, propagate by turning ratios, and leave either at a
boundary sink or **mid-link**, having reached a local destination.

Demand design determines what an experiment can show, so getting this subtly wrong is
expensive and invisible.

## Contract
Implement `DemandSpec` and its components exactly as `05_DOMAIN_MODEL.md` §6.1 specifies.

```python
def build_routes(net: Network, spec: DemandSpec, seed: int, out: Path) -> Path:
    """Emit SUMO route/flow files. Returns the path passed to Backend.start()."""
```

Realisation, per `D-022` and confirmed by T0.5: `<flow>` with exponential headways for
Poisson arrivals; `jtrrouter` for turn-ratio routing with declared sink edges; `departPos`
for mid-link sources; `arrivalPos` for mid-link attrition.

**Rates are a fraction of the receiving approach's saturation flow**, not absolute veh/h, so
"demand level 0.8" means the same loading across geometries. Saturation flow is computed from
lane count and speed limit; document the formula used.

Seeded from the `demand` stream only (`D-017`).

## Scope
1. `DemandSpec` → SUMO route files.
2. Saturation-flow computation and the fraction-to-absolute conversion.
3. Per-edge attrition applied at route construction: locally-destined vehicles get routes
   terminating at a sampled `arrivalPos` on that edge.
4. Vehicle type mix (cars only at M1, but the parameter exists so M4 needs no schema change).
5. Log the count of route generations that hit `jtrrouter`'s maximum-edges limit — the
   memoryless-routing artifact `D-022` warns about.

## Non-goals
1. Do NOT implement time-varying demand. That is M8.
2. Do NOT implement route choice or re-routing. Routes are fixed at insertion — deliberate,
   because route choice would make control effects unattributable.
3. Do NOT implement OD matrices. Turning ratios only.
4. Do NOT make attrition a single global rate. Per-edge, per `D-022`.

## Acceptance criteria
- [ ] Arrival headways are statistically consistent with the configured Poisson rate
      (Kolmogorov–Smirnov against the exponential, on ≥ 10,000 arrivals).
- [ ] The same seed produces byte-identical route files. Different seeds do not.
- [ ] Configured attrition rate matches the realised fraction of mid-link arrivals within
      tolerance, verified against `tripinfo`.
- [ ] Turn ratios per (junction, from-edge) sum to 1.0 and the realised split matches within
      tolerance.
- [ ] Demand level 0.8 produces comparable loading on a 2-lane and a 3-lane approach.
- [ ] The max-edges-limit counter is logged even when zero.

## Escalate if
1. T0.5 found that mid-link arrivals are not distinguishable in `tripinfo` — the three-way
   accounting in `07_EXPERIMENT_METHODOLOGY.md` §4 depends on it.
2. `jtrrouter` cannot express per-edge attrition and an alternative realisation is needed.
3. The saturation-flow formula requires a judgement call not fixed by `D-022`.
