# T1.14 — Signal display: from the constraint layer to SUMO and back

**Archetype:** Builder · **Depends on:** T1.3, T1.4, T1.7 · **Implements:** `D-034`, `D-023`

## Context
Added 2026-10-07 from T1.4's audit. Two halves of one translation are missing:

- **Outbound.** The constraint layer decides *what* the signal shows (a phase green, a yellow,
  an all-red) and `Backend.apply()` takes a red/yellow/green string. Nothing builds the string.
  During a yellow the constraint layer already names the *target* phase, so it no longer says
  which links should be yellow.
- **Inbound.** `TrueState.signals` reads SUMO's program phase index, which is always 0 once a
  controller drives the light (SUMO switches to its `online` program; verified on 1.27.1). The
  signal half of `TrueState` is meaningless in every controlled run.

## Contract
```python
# traffic_lab/backend — the only package that knows SUMO's state characters
def display_state(
    network: Network, intersection: IntersectionId, stage: SignalStage, phase: PhaseId | None
) -> str:
    """GREEN: 'G' on `phase`'s green links. YELLOW: 'y' on `phase`'s (the phase being left).
    ALL_RED: `phase` is None, all 'r'. Every other link 'r'."""

# traffic_lab/control — ConstraintLayer gains one read-only method
def display(self, intersection_id: IntersectionId) -> tuple[SignalStage, PhaseId | None]:
    """What the signal must show now: (GREEN, active), (YELLOW, phase being left), (ALL_RED, None)."""

# Backend.start gains the canonical network, keyword-only
def start(self, net: Path, routes: Path, cfg: BackendConfig, *, network: Network) -> None: ...
```
Green links come from `green_link_indices()` (T1.3). `'g'` is not emitted at M1: no scenario
declares a permitted pair (`D-023`, point 4).

**Decoding (`D-034`).** A displayed string whose green link set equals exactly one phase's is
that phase, green. Any other display is a transition: `in_transition=True`,
`green_started_s=None`, and `active_phase` stays the phase being left. A phase's
`phase_started_s` is the step its incoming transition began — or the start time, for the first
phase. Decoding never reads SUMO's phase index or `spent_duration`; drop them from `RawSignal`
(`D-003`'s inclusion test) and adapt the snapshot sidecar.

## Scope
1. `display_state()` and `ConstraintLayer.display()`.
2. Decoding in `Projector`; `Backend.start(..., network=)`; every existing caller and test updated.
   Tests on the M0 reference net obtain its `Network` from T1.3's parser.

## Non-goals
1. Do NOT add a controller or a runner. The acceptance test drives the loop by hand.
2. Do NOT emit `'g'`, and do NOT keep links green across a transition. Both are scenario-design
   features for later milestones.
3. Do NOT read the constraint layer from the backend or the backend from the constraint layer.
   The test composes them; T1.11's runner will.

## Acceptance criteria
- [ ] **The two views agree outside transitions.** Drive `SumoBackend` with a `ConstraintLayer`
      for at least five full cycles on a T1.3-generated intersection, including forced
      max-green overrides, applying `display_state(*layer.display(i))` every step. Whenever the
      layer's `SignalState.in_transition` is false, `TrueState`'s `SignalState` equals it
      exactly; during a transition, `TrueState.active_phase` is the phase being left.
- [ ] Under the static program, before any `apply()`, decoding produces the same phases the
      program shows — the decode does not depend on who drives the light.
- [ ] Byte-identical `TrueState` across transports still holds.
- [ ] A display matching no phase and no transition pattern (two phases' greens at once)
      raises rather than guessing.

## Escalate if
1. Two phases of one intersection share an identical green link set (`D-034`'s revisit trigger).
2. Any SUMO behaviour makes the displayed string differ from the one applied.
