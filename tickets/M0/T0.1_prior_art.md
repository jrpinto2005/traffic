# T0.1 — Prior art review and build-vs-reuse decision

**Archetype:** Spike
**Milestone:** M0
**Depends on:** T0.0
**Implements decisions:** informs `D-013`, `D-020`; closes `01_CRITICAL_REVIEW.md` G-9
**Time box:** generous — this is the highest-leverage ticket in M0

## Context
Four projects overlap heavily with what we are about to build: `sumo-rl`, RESCO, LibSignal,
and PyTSC. Per `02_PROJECT_CHARTER.md` §2.1 Consequence 3, reimplementing them is a
legitimate learning choice; reimplementing them **without having read them** is not, because
it forfeits free design review and produces results that cannot be compared to published
numbers.

## Questions
1. For each project: what does it do, what is its scenario format, what action-space
   convention does it use, which baselines does it implement, and how does it define its
   metrics?
2. **Where do their metric and action conventions differ from ours** (`D-006`, `D-020`,
   `D-025`)? Every divergence is a place our numbers will not be comparable to theirs, and we
   need to know which ones we chose deliberately.
3. RESCO reports roughly 11% improvement of MPLight over Max-Pressure. What exactly is being
   measured there, on what networks, and what would we have to match to claim a comparable
   number?
4. Per component — environment wrapper, baseline controllers, scenario format, metrics,
   analysis — **build or reuse?**

## Method
Read the source. Run at least `sumo-rl`'s single-intersection example and one RESCO scenario.
Reading the papers is not sufficient; the conventions live in the code.

## Deliverable
`research/M0_prior_art.md` containing:
- One section per project: purpose, scenario format, action space, baselines, metrics.
- A comparison table of **their conventions vs. ours**, flagging every divergence.
- An explicit build-or-reuse recommendation **per component**, with reasoning.
- A list of specific things worth copying (conventions, test scenarios, parameter values).

## Non-goals
1. Do NOT adopt any of these libraries as a dependency in this ticket. The decision is the
   deliverable; adopting is a later, separate decision.
2. Do NOT write any code destined for `traffic_lab/`.
3. Do NOT benchmark performance. That is T0.3.

## Escalate if
1. A project's action-space or metric convention is so different from `D-020` / `D-006` that
   comparability looks impossible — that is a decision-level finding, not a detail.
2. One of them already does substantially everything M1–M3 plan to do. **Say so plainly.**
   That would be a genuine and useful finding, not a failure.
